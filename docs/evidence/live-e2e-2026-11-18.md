# Live end-to-end run evidence — 2026-11-18

Two real runs of the rostr master/worker runtime with **mock mode off**
(`gateway mock mode: false` — the driver hard-refuses mock), against a free
local instruct model (SmolLM2-360M-Instruct Q4_K_M, llama.cpp server,
OpenAI-compatible endpoint, $0, no vendor account). Driver:
`scripts/e2e-live-run.ts`. Run record of run 1: `e2e-live-run-870555f0.json`.

## What ran (real, verified from the run records)

- Master decomposed the goal into subtasks through the live model.
- NPAO triage classified and ordered the subtasks.
- PAL compiled a typed manifest per task; `validateManifest` gated each.
- Workers executed **real allow-listed tool calls**: `list_dir` returned the
  actual workspace files (`README.md`, `e2e-runs`); `read_file` returned the
  real README content.
- The tool registry **refused hallucinated tool names** live:
  `error: tool '<tool_name>' is not allowed for skill 'workspace-inspector'`.
- Every task got an independent verification pass; failing tasks are marked
  failed in the record, not silently passed.
- Run records persisted by JsonHub (status `done`, 21 steps in run 1).

## Honest limitation

A 360M-parameter model is too weak to drive the loop cleanly: decomposition
parroted NPAO vocabulary ("NECESSITY", "Anxiety → PRIORITY"), workers echoed
schema placeholders, and 3/4 tasks in run 1 failed verification (1/4 done).
The harness plumbing is proven live; output quality needs a real instruct
model. Set `AI_GATEWAY_API_KEY` + `ROSTR_GATEWAY_URL` to any OpenAI-compatible
endpoint (Vercel AI Gateway default; OpenRouter: https://openrouter.ai/api/v1/chat/completions)
and re-run `scripts/e2e-live-run.ts`.
